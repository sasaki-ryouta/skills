# 裁定 JSON を受け取る

用語と論点の種類は [SKILL.md](SKILL.md) にある。

1. **照合する。** `schema` が `decision-sheet/1` か、`source.sha` が `source.repo` の既定ブランチの最新（fetch してから）と同じかを確かめる。sha が古ければ、`git diff --stat <sha>..origin/<既定ブランチ>` でその間の変更が触れる論点を挙げ、そのまま進めるかを人に聞く。
   完了：照合の結果を1行で伝えた。
2. **処理先に落とす。** 論点ごとに、`decision` の値から下の表の処理を決める。推奨と違う裁定も、その裁定どおりに進める。案の中身は `label` と `memo` から読む。
   完了：すべての論点が表のどれかの行に落ちている。
3. **記録する。** `issue` のある論点は、issue へのコメント「裁定：<label>（`<decision>`、推奨 `<recommended>`、`<via>`）」、メモ、シートの URL を用意する。投稿してよいかを人にまとめて1回聞いてから投稿する。
   完了：issue のある論点すべてに、裁定が残っているか、残さない理由を人から聞いている。
4. **報告する。** 処理した内容を論点ごとに1行で伝え、続けて次の4つを一覧にして返す：`undecided` の論点、小問が `undecided` の論点、メモが空の `none`、`via` が `bulk` の論点。
   完了：一覧を返した（4つとも空なら「すべて1つずつ裁定済み」と書く）。

## 裁定 JSON（decision-sheet/1）

この節が JSON の形の唯一の定義である。shell.html の書き出しはこれに従う（`check.test.mjs` がこの形で書き出しを検査する）。

```json
{
  "schema": "decision-sheet/1",
  "sheet": "example-app-2026-10-05-daily-tip",
  "title": "業務アプリ 裁定シート 10/5",
  "source": { "repo": "example/app", "sha": "4dd2c26" },
  "exportedAt": "2026-10-05T03:00:00.000Z",
  "decisions": [
    { "topic": "tip", "kind": "detail", "issue": null, "decision": "A", "label": "一日の流れで並べる",
      "recommended": "A", "via": "pick", "sub": { "scope": "daily" }, "memo": "" }
  ],
  "note": ""
}
```

- `decisions` はシートの画面の順に、すべての論点を含む。`sub` は小問のある論点だけにあり、答えていなければ `undecided`。一括で埋めるのは未裁定だった論点の小問だけなので、その論点の `via` が小問にも当てはまる。
- `via` は、人が1つずつ選んだなら `pick`、「残りを推奨で埋める」で入ったなら `bulk`、未裁定なら `null`。`bulk` も有効な裁定として扱う。
- `label` は選ばれた値の名前で、未裁定なら `null`。

| `decision` | 論点 | 意味 | 処理 |
| --- | --- | --- | --- |
| 案の key | 形・細部 | その案を採る | 採った案で実装するか、実装の issue を立てる。メモの条件を反映する |
| `current` | 形・細部 | 現状のままにする | 現状維持を記録する |
| `fix` | 対比 | 実装を設計に合わせる | 実装を直す issue を立てる |
| `amend` | 対比 | 設計の方を変える | 設計書を直す |
| `hold` | すべて | 保留する。待つものはメモにある | 保留として記録し、待つものをメモから書き写す |
| `none` | 形・細部 | どの案も採らない。方針はメモにある | メモの方針に従う。メモが空なら手順 4 の一覧に入れる |
| `undecided` | すべて | まだ選んでいない | 手順 4 の一覧に入れる |
