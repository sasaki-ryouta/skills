# process-pre-eval

評価アプリに自己評価を入れる前に、対象月のアクティビティから 5 項目のプレ評価と根拠を作る。毎月同じ手順・同じ書式で作り、上司評価とのずれを月ごとに追う。

## 置き場所

- 保存先は `~/Documents/workspace/evaluations/`。worktree の外に置き、翌月も読めるようにする。
  - `YYYY-MM_process_pre_evaluation.md` — 月ごとのレポート
  - `history.md` — 点数履歴の唯一の正本（プレ評価・自己・上司）
- 収集の生データは scratchpad の `collect-YYYY-MM/` に置く。

## 手順

1. **対象月を決める。** 指定がなければ前月。評価アプリの入力期限は毎月 10 日。
   完了: `YYYY-MM` が 1 つに決まっている。
2. **history.md を更新する。** 評価アプリの画面が添付されていれば、写っている月の自己・上司の点をすべて写す。添付がなければ未入力のまま進め、レポートの留意点に書く。
   完了: 画面に写っている月がすべて history.md と一致している。
3. **集める。** `collect.sh YYYY-MM <scratchpad>/collect-YYYY-MM` をバックグラウンドで実行する（10 分前後）。待つ間に前月のレポートを読み、「次月に向けた改善候補」を控える。
   完了: `summary.md` ができていて、コミットの「取得失敗の日」が 0。失敗した日があれば数分おいて、その日だけ `gh api` で取り直す。
4. **読む。** `summary.md` と抽出ファイル（`chat/my_space_msgs.tsv`、`chat/mentions_of_me.tsv`、`chat/my_dm_msgs.tsv`、`calendar.tsv`、`gh/` 配下）を読み、[REPORT.md](REPORT.md) の「項目別の観点」で根拠を集める。気になる Issue・PR は `gh` で本文まで確かめる。
   完了: 下の「減点材料の点検」の全行に、該当あり（日付と出典つき）か該当なしを付けている。
5. **採点する。** 下の「採点の規則」に従い、項目ごとにプレ評価と上司予測を決める。
   完了: 5 項目すべてに、加点と減点の根拠が 1 件以上ずつ並んだうえで点が付いている（根拠が見つからない側は「なし」と書く）。
6. **書く。** [REPORT.md](REPORT.md) の書式で `YYYY-MM_process_pre_evaluation.md` を保存し、history.md のプレ評価の列を埋める。
   完了: レポートの全節が埋まり、history.md の該当月にプレ評価の点が入っている。
7. **報告する。** レポートを SendUserFile で送る。チャットにはサマリ表（項目・プレ評価・上司予測・主な根拠）と、減点材料の上位 3 件だけを書く。

## 減点材料の点検

減点材料は自分からは表に出にくい。次の各行を毎月すべて当たる。

- **宙に浮いた依頼** — 自分が出した依頼と自分宛ての依頼のうち、月末までに完了か取り下げの記録がないもの。`mentions_of_me` と `my_space_msgs` を突き合わせる。
- **緊急・顧客向けの対応日数** — 【緊急】・不具合・問い合わせの Issue や PR が、作成からクローズ・マージまでにかかった日数。
- **辞退・欠席した会議** — `calendar.tsv` の declined と、会議メモで名前の出た回数が 0 のもの。前月から続いているかも見る。
- **直前の取り消し・日程変更** — 前日以降に断った同行や打ち合わせ。
- **全社スペースでの発言** — 0 件が続いていないか。
- **指導・注意を受けた場面** — 手順の誤りを指摘された件と、その後の是正。
- **前月の改善候補** — 前月レポートの「次月に向けた改善候補」それぞれが、今月どうなったか。
- **他者 PR への応答** — レビュー依頼が来たまま応えていない PR。

## 採点の規則

- 3 が標準。加点と減点の根拠を並べてから点を決める。
- 根拠は「日付・相手・何をしたか」で書き、出典（Issue 番号、スペース名）を添える。
- 上司予測は、history.md の自己と上司の差の傾向から項目ごとに出す（「3〜4」のような範囲でもよい）。2 か月以上差が続く項目は、レポートに理由の仮説を書く。
- DM の私的な会話は件数に数えるだけにして、中身は引用しない。
- コミット時刻には AI エージェントの無人実行が含まれるので、勤務時間の根拠にしない。
